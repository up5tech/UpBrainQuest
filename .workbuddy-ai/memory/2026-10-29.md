## Phase 3 — Core Session Engine and IQ Challenge (implementation)

Implemented the full Phase 3 scope per PLAN §2.2/§3.2/§4/§5.7/§9.2. Code written;
**not yet verified** (this session has no shell/command tool). User must run verification.

### Architecture
Pure-Dart, fully unit-testable domain (selection + evaluation + scoring), a
Repository/Provider boundary for content, a Riverpod `AsyncNotifier` session state
machine, three interaction mechanics matching the content schema, and an honest UI
(no fake scores; EQ excluded from the IQ denominator; explicit disclaimer).

### Domain engine — `lib/domain/session/` + `lib/domain/scoring/`
- `game_mode.dart` — `GameMode` enum (quickQuest/iquest/daily…) + `GameModeX`
  (`key`, `tryParse`).
- `session_request.dart` — `SessionRequest` (mode, count, optional difficulties,
  recent ids, seed, content-pack + score-algorithm versions).
- `selection_error.dart` — `QuestionSelectionFailure implements Exception` (throws
  instead of returning fewer questions than requested).
- `player_answer.dart` — sealed `PlayerAnswer` (`Unanswered`/`SelectedOption`/
  `Sequence`/`Reorder`); answers are immutable once recorded.
- `answer_evaluation.dart` — `AnswerEvaluation` + top-level `evaluateAnswer`:
  MC/puzzle scored with `pointsWeight`; EQ carries `isCorrect == null` + rubric.
- `session_plan.dart` — `SessionPlan` (items + mode).
- `session_builder.dart` — `SessionBuilder`: `candidates`/`candidateCount`, static
  `accepts(mode, item)` (iqChallenge→iq|puzzle; eqChallenge→eq; puzzleSprint→
  puzzle; quick/daily→all), `build` (no duplicates, recent-ID avoidance,
  deterministic via injected `Random`, throws on insufficient pool).
- `session_result.dart` — `SessionResult` (mode, questions, answers, evaluations,
  iqScore, completedAtUtc, `correctCount`/`objectiveCount`).
- `scoring/iq_score_calculator.dart` — `IqScoreCalculator`

### Gotchas learned
- App-boot widget tests must override `appDatabaseProvider` with
  `AppDatabase(NativeDatabase.memory())`; otherwise `path_provider` throws
  `MissingPluginException` and the DB-backed Home/Progress fail.
- `NativeDatabase.memory(setup: ...)` runs before Drift's migration, so it is the way to
  stage a v1 database for a migration test.
- Drift stores `DateTime` as `INTEGER` by default (the v1 table SQL must match).
- A provider callback that throws (`() async => throw ...`) is captured as `AsyncError`;
  a pre-built `Future.error` can leak an unhandled exception in tests.
