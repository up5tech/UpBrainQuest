## Key technical decisions (with reasons)

1. **Did NOT use `drift_flutter`.** It still pulls `sqlite3_flutter_libs` and
   `sqlcipher_flutter_libs`, both marked `+eol` and obsolete since `package:sqlite3` 3.x
   (SQLite is now bundled via Dart build hooks). Used `drift` + `sqlite3` +
   `path_provider` directly instead. Verified: `sqlite3.framework` is bundled in the
   iOS app and the DB works on-device.
2. **Did NOT use `custom_lint`.** It conflicts with `drift_dev` 2.35.x on
   `analyzer`/`dart_style` ranges. `riverpod_lint` 3.x is an analysis-server plugin and
   needs no `custom_lint` dependency.
3. `sqlite3: ^3.8.0` pinned directly to get the newest 3.x (transitive resolution
   otherwise settled on 3.5.2).
4. Resolved versions: flutter_riverpod 3.4.3, go_router 18.1.1, drift 2.35.3,
   drift_dev 2.35.2, shared_preferences 2.5.6, intl 0.20.3, json_serializable 6.15.2,
   build_runner 2.17.1, analyzer 14.6.0.

## Gotcha that cost time

`drift_dev` reports `type 'FunctionExpressionInvocationImpl' is not a subtype of type
'MethodInvocation' in type cast` when a column expression is malformed — for example
`dateTime()()();` (an extra `()`) instead of `dateTime()();`. The real cause is a typo
in the column getter, not a package or version incompatibility. The upstream drift docs
also show `text().withDefault(...)()` — note the trailing `()` — which is the drift 2.x
form; the drift 3 preview form drops it.
